# 动态层级 AI 推理研究工作协议

- 版本：0.1
- 日期：2026-07-30
- 状态：研究假设与首轮实验基线
- 用途：保存已达成的设计共识、区分事实与假设，并约束后续实现和实验不偏离原始问题。

## 1. 研究目标

研究一种用于序列推理的动态递归结构：

1. 同一个值或词元可以重复出现，但每次出现因位置、上下文和交互历史不同而拥有不同状态。
2. 模型不预设“词元、段落、章节、大纲”等固定语义层级。
3. 模型使用共享递归函数，根据内容和当前问题自行形成所需的抽象层级。
4. 连续状态在当前尺度内变化；当内部进度、冲突或不充分程度达到条件时，触发离散的结构操作。
5. 模型必须保留返回原始细节的路径，不能只留下不可逆摘要。

暂定研究对象名称为“动态递归层级推理模型”。名称仅用于沟通，不代表已形成新理论。

## 2. 已确认的事实

以下内容属于已有数学或机器学习机制，不作为本研究的新颖性主张：

1. 数值或词元的字面值相同，不代表上下文化后的内部状态相同。
2. 词元状态是上下文函数的输出，不是把整个上下文或函数完整装进单个词元。
3. 固定长度向量是对上下文的有损表示，不可能无损保存任意长历史。
4. 机器浮点数集合有限，不能无限产生从未出现过的新浮点值。
5. 动态计算深度、动态路由、上下文化表示和连续状态触发离散模式切换均已有相关研究。
6. 动态层级仍受最大节点数、运行时间、显存和算力限制；“不预设语义层级”不等于拥有无限物理计算能力。

## 3. 当前设计共识

### 3.1 不建立独立的新颖度字段

重复是合法且必要的。一个信息单元的身份由组合状态决定：

```text
状态 = 内容 + 位置/覆盖范围 + 上下文状态 + 交互历史 + 结构关系
```

即使两个单元拥有相同数值，只要位置、来源或上下文不同，整体状态就不同。

### 3.2 不把所有属性塞进一个浮点数

整数位和小数位的最初类比保留为设计直觉，但工程实现使用结构化状态：

```text
v_i = (h_i, R_i, b_i, C_i)
```

- `h_i`：内容及上下文向量。
- `R_i`：该节点覆盖的原始输入范围或来源集合。
- `b_i`：当前尺度内的连续相位、进度或不充分程度。
- `C_i`：子节点及其他结构引用。

如果以后加入离散层级标识 `d_i`，它表示递归深度、路由状态或激活尺度，不自动等于真实数学维度。

### 3.3 层级由共享递归函数生成

初始时，每个输入词元或符号是一个叶节点。候选节点之间计算交互分数：

```text
a_ij = G(v_i, v_j, query)
```

满足合并条件时，使用同一个共享函数生成父节点：

```text
v_k = F(v_i, v_j, query)
```

新节点仍可继续参与相同过程，因此递归深度由内容、问题和计算预算共同决定。模型不需要事先知道某层是短语、段落还是章节。

### 3.4 动态结构操作

长期目标操作集：

- `MERGE`：多个节点组成更高尺度节点。
- `LINK`：建立跨区域或跨层关系，但不合并。
- `EXPAND`：摘要不足时返回子节点取回细节。
- `SPLIT`：发现错误抽象时拆开已有节点。
- `STOP`：当前表示足以回答问题，停止继续计算。

首轮实验只实现 `MERGE` 和 `STOP`。在这两项无法证明有效前，不加入其余操作。

### 3.5 连续相位不直接等于升层命令

相位按当前状态更新：

```text
b_i(t+1) = UpdatePhase(b_i(t), h_i(t), query)
```

相位到达边界时，只触发控制器重新决策：

```text
action_i = Controller(h_i, b_i, query)
```

控制器可以选择合并、停止或以后扩展出的其他操作。不能把每次越界硬编码为“固定升一级”。

为了避免 `0` 与 `1` 边界不连续，相位优先采用圆周表示：

```text
phase_i = (sin(2πb_i), cos(2πb_i))
```

是否需要相位变量本身仍是待验证假设，不能预设它必然优于普通门控标量。

### 3.6 结构应当依赖当前问题

同一份输入面对不同问题时，可以形成不同的抽象结构。模型学习的是“为当前任务组织信息”，不是恢复唯一正确的人类大纲。

最终结构更可能是：

```text
动态层级树 + 少量稀疏横向连接 + 指向原始节点的可追溯引用
```

树负责抽象和压缩，横向连接负责表达跨区域关系，原始引用负责防止摘要永久丢失细节。

## 4. 核心研究假设

- H1：共享递归合并能够形成对推理有用的内容依赖层级，而不是退化为固定分段。
- H2：动态层级在序列长度外推和嵌套推理上优于同参数、同计算预算的普通 Transformer。
- H3：连续相位能够提供比普通一次性门控更稳定的“处理进度”，帮助模型决定何时继续抽象。
- H4：保留原始节点引用并允许按需展开，可以缓解层级摘要造成的细节丢失。
- H5：模型形成的有效结构未必与人类段落或语法树一致；只要提升任务表现，就不能仅因不可读而判定失败。

其中 H1-H4 都是待实验验证的推测，不是已确认结论。

## 5. 明确不作出的主张

1. 不声称该构想已经构成新的训练理论。
2. 不声称每个词元完整包含全部上下文。
3. 不要求每个新状态使用从未出现过的浮点值。
4. 不把整数值天然解释为真实向量维度。
5. 不认为动态层级可以突破有限算力和有限记忆。
6. 不假设模型学到的结构必然像人类文章大纲。
7. 不在没有对照实验时把训练成功等同于机制有效。

## 6. 首轮实验范围

### 6.1 推荐模型规模

首轮正式实验目标为约 4M-8M 参数：

- 隐藏维度：256
- 注意力头：4
- 基础块：4 个，或 1-2 个共享块递归使用
- FFN 维度：1024
- 最大输入长度：256
- 最大递归步数：8
- 初始词表：128-512
- 数值精度：优先 BF16；不支持时使用 FP32 或稳定的 FP16 配置

该规模用于验证机制，不用于证明大模型尺度上的收益。

### 6.2 首轮任务

数据优先自动生成，以便精确控制难度和真实结构：

1. 重复符号在不同位置承担不同角色。
2. 多层括号和表达式求值。
3. 变量绑定、覆盖和跨距离引用。
4. 多条局部事实经过若干组合步骤才能得到答案。
5. 训练使用较短序列，测试使用 2 倍和 4 倍长度。

不把人工段落标签直接提供给主实验模型，避免模型只是模仿预设层级。

### 6.3 必需对照

所有模型尽量匹配参数量和有效计算量：

- A：普通小型 Transformer。
- B：共享递归模型，使用普通门控决定 `MERGE/STOP`。
- C：共享递归模型，使用连续相位辅助决定 `MERGE/STOP`。
- D（诊断上界，可延后）：使用数据生成器真实结构的递归模型。

D 用于判断“层级结构本身是否有帮助”。若 D 都不能优于 A，则无需继续优化学习结构的控制器。

### 6.4 验收指标

- 训练分布内准确率。
- 2 倍及 4 倍长度外推准确率。
- 每个样本的平均递归步数和计算量。
- 同等计算预算下的准确率。
- 合并全部节点或完全不合并的结构坍缩比例。
- 摘要后仍能恢复关键原始细节的比例。
- 不同随机种子下结构和性能的稳定性。

首轮快速验证允许单随机种子。出现正向信号后，关键比较至少运行 3 个随机种子。

## 7. 分阶段实施顺序

### 阶段 0：建立可验证问题

1. 编写合成数据生成器。
2. 保存每个样本的真实依赖结构，但不默认提供给模型。
3. 定义训练长度、外推长度和准确率指标。
4. 验证普通 Transformer 能学会训练范围内任务。

### 阶段 1：验证递归结构是否值得学习

1. 实现普通 Transformer 基线 A。
2. 实现使用真实结构的诊断模型 D。
3. 比较 A 与 D 的长度外推。

若 D 没有稳定收益，暂停动态控制器开发，先重新检查任务是否真的需要层级推理。

### 阶段 2：学习动态合并

1. 实现共享递归函数。
2. 只允许相邻候选节点 `MERGE` 或 `STOP`。
3. 添加节点数和递归步数预算。
4. 检查“全部合并”和“完全不合并”两种退化。

### 阶段 3：验证连续相位

1. 在相同递归模型上分别使用普通门控和相位门控。
2. 保持参数量、训练数据和计算预算一致。
3. 检查相位是否与任务难度、递归步数和错误位置相关。

只有 C 稳定优于 B，才认为相位机制获得初步支持。

### 阶段 4：恢复细节与跨区域关系

依次加入：

1. `EXPAND` 和原始节点检索。
2. 稀疏 `LINK`。
3. 必要时再研究 `SPLIT`。
4. 最后才考虑动态激活隐藏维度或更大模型。

## 8. 失败条件与停止规则

遇到以下情况时，不通过堆模型规模掩盖问题：

1. 真实结构上界模型 D 不优于普通基线。
2. 动态模型长期坍缩为固定结构。
3. 相位门控与普通门控没有稳定差异。
4. 动态操作开销超过节省的计算且没有外推收益。
5. 摘要造成的细节损失无法通过检索恢复。
6. 结果只在单一随机种子或单一任务成立。

失败结果也应记录，因为它可以排除错误方向。

## 9. 工程与文档约定

1. 删除源文件前必须复检目标、确认替代内容并保留可恢复备份。
2. 每轮结构或训练目标变化前，先更新本协议的“决策记录”。
3. 每次实验记录模型配置、数据版本、随机种子、计算预算和结果。
4. 低重要性功能先做最小验证；若干轮实现后再整合完整测试。
5. 不以更大参数量替代公平对照。
6. 代码、数据生成器和实验配置应分离，保证任务变化不隐式改变模型。
7. 尚未验证的解释必须标为假设，不写成已确认事实。

## 10. 决策记录

### 2026-07-30

- 放弃“每个小数部分必须从未出现过”的要求。
- 使用上下文组合状态区分重复值。
- 放弃固定的词元、段落、章节、大纲枚举层级。
- 采用共享函数递归生成内容依赖、问题依赖的动态层级。
- 长期结构采用层级树、稀疏横向连接和原始细节引用。
- 首轮只实现 `MERGE/STOP`，避免一次引入过多自由度。
- 连续相位作为待验证机制，不预设其一定有效。
- 首轮模型控制在约 4M-8M 参数，并以合成推理任务进行公平对照。

## 11. 下一步

开始训练前首先完成阶段 0：定义一种确实需要动态层级、又能自动判分的合成任务。推荐从“嵌套表达式 + 重复变量绑定 + 长度外推”开始，因为它同时测试局部交互、递归结构、重复符号的上下文化和跨长度泛化。

### 2026-08-09 Stage 2 R2 决策

- 否决三表达式 R1 草案：它主要测试查询相关的算力分配，单一固定解析树仍可能解释结果。
- R2 改为“同一条无括号表达式、不同运算优先级查询”。查询改变正确的归约顺序、树和答案；生成完成后才派生全部查询与答案，不按目标反解输入。
- R2 只验证普通门控的相邻 `MERGE` 顺序并执行 `STOP` 语义；连续相位、可变有用停止、`LINK`、`EXPAND` 和 `SPLIT` 继续延期。
- 必须同时比较参数匹配和实测计算匹配的查询感知 Transformer、无结构共享递归、查询盲路由、查询置换 sham、全部固定策略、查询条件动态路由、D-true 与 D-sham。
- 不把“不同查询产生不同轨迹”单独当作成功；还必须证明硬路径因果隔离，并优于查询盲、固定结构、sham 和等计算对照。
- `docs/stage2-construction-packet-r2.md` 只授权实现、测试和一次 `calibration_only` 运行。候选正向门槛、正式多种子训练和连续相位仍未授权。

### 2026-08-09 Stage 2 R2 校准结论

- R2 已实现同输入双查询数据、硬路径相邻合并、查询盲/置换/fixed/递归/平坦/D 对照、family 隔离、统一计算记录和 checkpoint 恢复。
- DirectML 校准完成 120 次更新。三个评估 profile 各含 420 个独立 base family，训练与评估重叠为零。
- B-query 在三个评估中都对全部样本立即 `STOP`，与 F-stop 轨迹相同；A、B、D-true 和 D-sham 的准确率均仍接近七分类随机水平。
- 该结果只能说明本次校准没有建立任务学习，且候选控制器发生停止坍缩；它不能证明动态层级无效，也不能支持动态层级有效。
- R3 必须先设置任务学习可行性门。对于必须得到完整表达式结果的 benchmark，候选 B 只学习 `MERGE` 顺序，不再把 `STOP` 作为合法动作；可变停止另设能从部分结构作答的任务。
- 在 D-true 或其他任务学习参照未稳定高于随机水平、B 未摆脱固定/停止坍缩前，不进入多种子候选、连续相位或自然语言实验。
